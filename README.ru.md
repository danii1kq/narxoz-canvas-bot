# narxoz-canvas-bot

> **Статус: проект заморожен.** Разработка остановлена. Работать он умел, но
> держать развёртывание живым не получилось: бот постоянно спрашивает у API
> Canvas статус заданий и оценок, и в итоге университет заблокировал IP
> сервера, на котором бот крутился. Код сохранён как есть и по-прежнему
> запускается, но обновлений не будет. Перед повторным запуском прочитайте
> разделы [Почему проект заморожен](#почему-проект-заморожен) и
> [Прокси (CANVAS_PROXY)](#прокси-canvas_proxy).

Telegram-бот, который следит за **заданиями** и **оценками** в Canvas LMS
университета Narxoz (`https://canvas.narxoz.kz`) и присылает уведомления на
**русском языке**: когда появляются новые задания, выставляются оценки, работа
отправляется, а дедлайны приближаются или проходят.

**Языки:** [English](README.md) | [Русский](README.ru.md)

- Язык: **Go 1.27+** (без CGO, используется `modernc.org/sqlite`).
- Telegram: `go-telegram-bot-api/v5`; ограничение частоты: `golang.org/x/time/rate`.
- Все сообщения для пользователя на русском; код, комментарии, логи и этот
  README на английском.
- Все дедлайны показываются и считаются в **Asia/Almaty (UTC+5)**.

## Почему проект заморожен

Чтобы знать статус каждого задания, боту приходится непрерывно спрашивать
Canvas:

- каждые `POLL_INTERVAL` (по умолчанию 5 минут) он запрашивает
  `GET /api/v1/courses`, а затем `GET /api/v1/courses/:id/assignments` по
  **каждому** активному курсу, проходя все страницы пагинации;
- токен проверяется запросом `GET /api/v1/users/self` при сохранении и при
  ручном обновлении;
- задача напоминаний **не** обращается к Canvas: она работает по локальному
  снимку данных в SQLite, то есть дополнительного трафика не создаёт.

У студента с 8-10 курсами это примерно 10-12 запросов каждые пять минут,
порядка 3 000 запросов в сутки, и все они с одного и того же IP. Встроенный
ограничитель частоты пропускает около 10 запросов в секунду (лимит Canvas), так
что этот режим он совершенно не сглаживает. Для университетского сервера
такой трафик неотличим от скрейпинга, и IP в итоге заблокировали: запросы
висят до таймаута, а бот пишет «Canvas не ответил на проверку».

Два практических вывода:

1. Проект заморожен, а не сломан. Код делает свою работу, но держать
   развёртывание с заблокированного адреса не получилось.
2. Перед повторным запуском либо увеличьте `POLL_INTERVAL` (например `1h` или
   `6h`, это уменьшает трафик в 12-72 раза), либо пустите бота через прокси с
   незаблокированным адресом. Смотрите раздел
   [Прокси (CANVAS_PROXY)](#прокси-canvas_proxy).

Из той же причины следует третье правило: трафик к Canvas должен идти через
**казахстанский IP**. Сервер в Казахстане подходит как есть; сервер в любом
другом месте требует включённого прокси.

Данные при этом не теряются: база SQLite с настройками, отключениями курсов и
зашифрованными токенами остаётся в томе `bot-data`, поэтому бот продолжает с
того места, на котором остановился.

## Прокси (CANVAS_PROXY)

**Правило:** трафик к Canvas должен идти через **казахстанский IP**.

- Бот работает в Казахстане: ничего делать не нужно, прокси остаётся
  **выключенным**.
- Бот работает в другом месте: прокси нужно **включить** и указать в нём
  казахстанский адрес (казахстанский VDS, локальный прокси в Казахстане,
  домашняя линия). Иначе университет видит запросы с незнакомого адреса и
  блокирует его, из-за чего этот проект и был остановлен.

`CANVAS_PROXY` направляет **только трафик к Canvas** через прокси HTTP(S) или
SOCKS5. Telegram по-прежнему ходит напрямую, и больше в проекте ничего не
меняется.

```dotenv
# .env
CANVAS_PROXY=socks5://user:pass@kz-proxy-host:1080
```

**Прокси по умолчанию выключен.** Пустое значение означает, что трафик к
Canvas уходит напрямую с сервера, и это правильный вариант для сервера в
Казахстане. Неверное значение отклоняется при запуске с понятной ошибкой, а не
молча игнорируется: молча продолжив без прокси, мы отправили бы трафик ровно
с того адреса, который блокируют.

**Что это даёт**

- **Казахстанский исходный IP для Canvas.** Университет блокирует адрес
  дата-центра, а не адрес прокси. Прокси в Казахстане оставляет бота
  рабочим, даже если сам сервер заблокирован.
- **Выход из заблокированного или отфильтрованного маршрута.** Часть
  провайдеров вообще не даёт открыть `canvas.narxoz.kz`: соединение висит до
  таймаута. Прокси даёт рабочий маршрут.
- **Одну точку управления.** Если адрес прокси меняется, меняется только
  `.env`, а бот перезапускается уже с новым маршрутом.

**Чего это не даёт**

- Количество запросов не уменьшается. Режим опроса остаётся прежним, поэтому
  `POLL_INTERVAL` тоже нужно увеличить.
- На Telegram это не влияет: Bot API вызывается всегда напрямую, поэтому бот
  продолжит работать, даже если прокси лежит.
- Токен не спрятан от прокси, который пишет логи трафика. Пользуйтесь тем
  прокси, которому доверяете.

**Как это работает**

- Допустимые схемы: `http`, `https`, `socks5`, `socks5h`.
- Прокси используется только для `CANVAS_BASE_URL`; переменные окружения
  `HTTPS_PROXY` / `HTTP_PROXY` остаются в силе для остальных запросов, так
  как их понимает стандартная библиотека Go.
- При старте в лог пишется состояние прокси (`canvas_proxy`), а клиент Canvas
  отдельно логирует хост, через который идут запросы.
- Ошибки, связанные именно с прокси (неверный адрес, DNS, отказ соединения),
  показываются в чате отдельным сообщением вместо общей ошибки Canvas.


## Возможности

- **Чат только с уведомлениями.** Новые задания, оценки, отправленные работы,
  напоминания и сообщения о просроченных дедлайнах приходят в виде сообщений;
  больше ничего туда не пишется. Кнопка **Открыть** рядом с полем ввода
  (кнопка меню Telegram) открывает Mini App.
- **Mini App (Telegram Web App)**: задания / не сдано / просрочено / оценки /
  курсы / настройки с отключением курсов, временем напоминания, ручным
  обновлением Canvas и диалогом для токена Canvas. Личность берётся из
  подписанного `initData` от Telegram (HMAC-SHA256 с токеном бота), поэтому
  паролей нет, а приложение можно ограничить владельцем из
  `TELEGRAM_CHAT_ID`.
- **Токен Canvas из чата или из приложения**: `CANVAS_API_TOKEN` необязателен.
  Вставьте токен в `/setup` (сообщение с токеном удаляется сразу же) или в
  приложении; он проверяется запросом `/api/v1/users/self`, хранится по чату
  (AES-256-GCM или base64-обфускация, см. `CANVAS_TOKEN_SECRET`), а если Canvas
  недоступен, сохраняется и проверяется в фоне, чтобы не спрашивать заново.
  Он переживает перезапуски; `/disconnect` удаляет его.
- **Синхронизация данных** каждые `POLL_INTERVAL`: забираются активные курсы и
  их задания (вместе с отправкой), затем идёт сверка с SQLite. Обрабатываются
  **все** страницы пагинации, есть повторы с задержкой при 429/5xx, таймаут на
  каждый запрос и ограничение частоты по лимиту Canvas (около 10 запросов/с).
- **Уведомления**: 🆕 новое задание, ✅ выставлена оценка, 📤 работа отправлена,
  ⏰ дедлайн заранее (настраиваемый интервал 24ч/12ч/6ч), 🔥 за час до
  дедлайна, ⚠️ «дедлайн прошёл, задание не сдано», отправляется **один раз**.
  Сданное задание везде отображается как «сдано».
- **Напоминания** (отдельное расписание) приходят только по **несданным**
  заданиям; отправка работы в любой момент отменяет дальнейшие напоминания.
- **Исчезающие курсы** помечаются неактивными (но не удаляются), поэтому
  временный сбой API не вызывает ложных уведомлений о новых заданиях. Курс,
  чей запрос не удался, сохраняет свои задания и дедлайны в поле зрения:
  одна сломанная пара не опустошает набор данных.
- **Команды остаются** как альтернатива приложению (`/status`, `/refresh`,
  `/setup`, `/mute`, ...); когда приложение настроено, они отвечают короткими
  сводками вместо интерактивных списков. Без `WEBAPP_URL` бот сохраняет полную
  клавиатуру меню и инлайн-списки, так что для чата ничего не ломается.
- **Уведомления идут только в личные чаты.** Чат подписывается на уведомления
  после **/start** в личном чате; группы не подписываются никогда, поэтому
  личные задания и оценки не утекут в группу. Диалог ввода токена работает
  только в личном чате: бот удаляет сообщение с токеном.
- **Надёжность**: JSON-логирование через `slog`, одноразовое уведомление об
  отсутствующем или истёкшем токене, восстановление после паники в обработчике
  обновлений и в задачах, корректное завершение по SIGINT/SIGTERM.
- **Бот никогда не зависает**: ручное обновление и первая синхронизация после
  `/setup` идут в фоне, а опросы выполняются по очереди, поэтому бот отвечает,
  пока Canvas обходится.

## Требования

| Что              | Версия / примечание                                                |
|------------------|---------------------------------------------------------------------|
| Go               | 1.27 или новее (только для локальной сборки; в Docker-образе он уже есть) |
| Docker + Compose | v2 или новее (рекомендуемый способ запуска)                         |
| Токен Canvas     | из Canvas: аватар → Account → Settings → Approved Integrations       |
| Токен Telegram   | от [@BotFather](https://t.me/BotFather)                              |
| Публичный HTTPS  | только для Mini App (сам чат работает и без него)                    |

Публичный сервер для работы бота **не нужен**. Он нужен только Mini App, которой
требуется доступный по HTTPS адрес; всё остальное работает с домашнего
компьютера.

## Установка

### 1. Создайте Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте имя и username, оканчивающийся на `bot`.
3. Скопируйте токен: это `TELEGRAM_BOT_TOKEN`.
4. По желанию: чтобы узнать свой `TELEGRAM_CHAT_ID`, нажмите **/start** у бота и
   посмотрите логи (id подписчика там записывается), либо спросите
   [@userinfobot](https://t.me/userinfobot).

> Если `TELEGRAM_CHAT_ID` оставить пустым, бот будет уведомлять каждый чат,
> который нажал **/start**. Для личного развёртывания это удобно.

### 2. Получите код

```bash
git clone <your-repo-url> narxoz-canvas-bot
cd narxoz-canvas-bot
```

### 3. Настройте конфигурацию

```bash
cp .env.example .env        # на Windows: copy .env.example .env
$EDITOR .env                # как минимум задайте TELEGRAM_BOT_TOKEN
```

`TELEGRAM_BOT_TOKEN` единственное обязательное значение. `CANVAS_API_TOKEN`
может остаться пустым: тогда бот попросит токен прямо в чате через `/setup` и
запомнит его в базе. Полный список переменных смотрите в разделе
[Конфигурация](#конфигурация).

### 4. Запустите

Docker Compose (рекомендуется):

```bash
docker compose up -d --build
docker compose logs -f bot
```

Локальная сборка на Go:

```bash
set -a; . ./.env; set +a      # экспорт переменных (Linux/macOS); на Windows: $env:X="..."
make run                      # или: go run ./cmd/bot
```

### 5. Подключите Canvas

Нажмите **/start**, затем отправьте `/setup` и вставьте токен Canvas. Бот
проверит его, удалит ваше сообщение и запустит синхронизацию. Подробности в
разделе [Подключение Canvas в чате](#подключение-canvas-в-чате).

## Конфигурация

Конфигурация читается из переменных окружения (подойдёт и файл `.env`) и
проверяется при запуске: если обязательное значение отсутствует или указано с
ошибкой, процесс завершится с понятным сообщением.

| Переменная              | Обязательна | По умолчанию             | Описание                                                                 |
|-------------------------|-------------|--------------------------|--------------------------------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`    | да          | -                        | Токен бота от @BotFather.                                                |
| `CANVAS_API_TOKEN`      | нет         | *(не задана)*            | Токен доступа к Canvas. Оставьте пустым и подключите Canvas через `/setup` в чате. Если задан, он используется для фоновой синхронизации. |
| `CANVAS_TOKEN_SECRET`   | нет         | *(не задана)*            | Ключ, которым шифруются введённые в чате токены (AES-256-GCM). Пусто, значит только base64-обфускация. |
| `CANVAS_BASE_URL`       | нет         | `https://canvas.narxoz.kz` | Адрес экземпляра Canvas.                                               |
| `CANVAS_PROXY`          | нет         | *(не задана, выключен)*    | Прокси только для трафика к Canvas (`http://user:pass@host:port`, `socks5://host:1080`). **По умолчанию выключен.** Включите, если сервер не в Казахстане: трафик к Canvas должен идти через казахстанский IP. |
| `TELEGRAM_CHAT_ID`      | нет         | *(не задана)*            | Основной чат для уведомлений. Если пусто, уведомляются все чаты, нажавшие `/start`. |

| `POLL_INTERVAL`         | нет         | `5m`                     | Период синхронизации (простое число означает минуты).                    |
| `REMINDER_INTERVAL`     | нет         | `30m`                    | Период работы напоминаний.                                               |

| `REQUEST_TIMEOUT`       | нет         | `30s`                    | Таймаут на один запрос к Canvas.                                         |

| `WEBAPP_URL`            | нет         | *(не задана)*            | Публичный HTTPS-адрес приложения, например `https://narxoz-bot.duckdns.org`. Включает кнопку **Открыть** и само приложение. |
| `WEBAPP_ADDR`           | нет         | `:8080`                  | Локальный адрес прослушивания за обратным прокси.                        |
| `WEBAPP_DEV_CHAT_ID`    | нет         | *(не задана)*            | Только для разработки: авторизовать локальный браузер как этот чат без Telegram. **Никогда не задавайте на публичном развёртывании.** |

## Подключение Canvas в чате

1. Запустите бота и нажмите **🔑 Canvas API** (или отправьте `/setup`).
2. Бот объяснит, как получить токен: Canvas → аватар → **Account** →
   **Settings** → **Approved Integrations** → **New Access Token** →
   **Generate Token**. Скопируйте токен сразу, Canvas показывает его один раз.
3. Отправьте токен одним сообщением. Бот:
   - отвечает «⏳ Проверяю токен в Canvas…»;
   - вызывает `GET /api/v1/users/self` с этим токеном и показывает
     пользователя Canvas, под которым произошла авторизация (или объясняет
     401/403);
   - **удаляет ваше сообщение** с токеном;
   - сохраняет токен по чату в зашифрованном виде (`CANVAS_TOKEN_SECRET`
     означает AES-256-GCM);
   - сразу опрашивает Canvas и показывает ваши настоящие задания.
4. Дальше пропущенные дедлайны и оценки приходят автоматически. `/canvas`
   показывает состояние подключения, `/disconnect` удаляет сохранённый токен,
   `/cancel` выходит из диалога, **🔄 Обновить** опрашивает Canvas по запросу.

Примечания:

- Если в `.env` задан `CANVAS_API_TOKEN`, он управляет фоновой синхронизацией
  для всех подписчиков; токены из чата всё равно используются для проверок по
  запросу в том чате, где их ввели.
- Без `CANVAS_API_TOKEN` фоновую синхронизацию ведёт **первый** подключённый
  токен из чата (в базе хранится один общий набор данных, бот рассчитан на
  личное использование). Токен, введённый в Mini App, никогда не перехватывает
  эту синхронизацию.
- В базе SQLite лежит зашифрованный токен. На общем сервере или VDS задайте
  `CANVAS_TOKEN_SECRET`, иначе токен будет только base64-обфусцирован, о чём
  бот пишет в лог при запуске.
- Диалог ввода токена работает только в **личном чате**: бот удаляет сообщение
  с токеном, и в группе этого делать нельзя.
- Первая синхронизация после `/setup` идёт в фоне, поэтому бот продолжает
  отвечать, пока обходится Canvas. Список придёт в чат чуть позже.

## Mini App (Telegram Web App)

### Что это

Приложение обслуживает сам процесс бота (`internal/webapp`), а HTTPS
завершает обратный прокси Caddy. Telegram открывает его по нажатию кнопки
**Открыть**, которую бот ставит рядом с полем ввода
(`setChatMenuButton` → `web_app`). Внутри всё то, что раньше делалось кнопками
в чате, собрано в одном интерфейсе, похожем на нативный.

HTTP-сервер запускается всегда, даже без `WEBAPP_URL`: так отвечает
`/healthz` и есть цель для обратного прокси. Сама кнопка **Открыть** в чате
зависит от `WEBAPP_URL`.

### Дизайн-контракт

Документ, чтобы будущие изменения оставались согласованными (этот раздел не
отправляется в браузер):

- **Назначение:** действие, то есть «что я сейчас должен, что изменилось,
  живо ли подключение». Это не маркетинговый и не читательский экран.
- **Унаследованная идентичность:** приложение работает внутри Telegram, поэтому
  использует собственный дизайн-язык клиента: цвета `--tg-theme-*`
  (светлая/тёмная тема), системный шрифт, сгруппированные строки списка,
  сегментированный переключатель, нижняя панель из трёх вкладок и шторка снизу.
  Свои только цвета статусов, и у каждого статуса есть ещё и текстовая подпись,
  так что цвет никогда не единственный сигнал.
- **Композиция:** липкая шапка (заголовок, чип подключения, время последней
  синхронизации, обновление), дальше либо переключатель фильтров со списком
  заданий (Задания), либо список курсов с переключателями отключения (Курсы),
  либо сгруппированные разделы настроек (Настройки). Строка: название (в две
  строки) + курс + правая колонка со статусом, дедлайном и баллом; нажатие
  открывает шторку снизу с полной записью и ссылкой на Canvas.
- **Типографика и цвет:** шкала 22/15/13 px, табличные цифры для дат и
  баллов; переменные темы Telegram с подобранными запасными значениями для
  браузеров (проверенный контраст: названия от 13,9 до 21:1, вторичный текст
  от 6,9 до 7,6:1, статус от 5,1 до 8,2:1).
- **Адаптивность:** одна колонка, `max-width: 720px`, отступы безопасной зоны,
  панель вкладок закреплена внизу; вёрстка проверена на 390x844 и 1280x800.
- **Обязательные состояния:** скелетоны загрузки, пустые состояния для каждого
  фильтра, баннер недоступного Canvas с кнопкой повтора, призыв подключить
  Canvas, форма токена (с подсказкой, где его взять), обратный отсчёт до
  следующего обновления, оптимистичные переключатели отключения курсов и
  времени напоминания с откатом, локальное уведомление «открыто вне Telegram».
- **Условие готовности:** все перечисленные состояния достижимы в браузере на
  настоящей базе, контраст проверен, диалог с токеном работает от начала до
  конца.

### Безопасность

- Каждый запрос `/api/*` обязан нести `initData` от Telegram
  (`Authorization: tma <initData>`), которые проверяются HMAC-SHA256 по
  отсортированному списку полей с ключом `HMAC_SHA256("WebAppData",
  bot_token)`; данные старше 24 часов отклоняются.
- API проверяет HTTP-метод: на изменяющие состояние эндпоинты запрос `GET`
  отвечает `405`, поэтому предпросмотр ссылки или краулер не запускают
  синхронизацию с Canvas.
- id пользователя Telegram используется как id чата, поэтому приложение и бот
  работают с одним и тем же токеном Canvas, отключениями и настройками.
- Если задан `TELEGRAM_CHAT_ID`, API отвечает только этому пользователю, иначе
  403. Без него приложение доступно любому пользователю бота, поэтому задайте
  его, если бот не строго личный.
- Проверка подключения показывает только собственный аккаунт Canvas
  пользователя, а токен, введённый в приложении, никогда не перехватывает
  фоновую синхронизацию.
- Приложение отправляет строгий `Content-Security-Policy` (только свои скрипты
  и SDK Telegram), `X-Frame-Options` и `X-Content-Type-Options`, в том числе
  когда работает без прокси Caddy.
- Статичная страница встроена в бинарник (`go:embed`); кроме скрипта SDK
  самого Telegram ничего стороннего не подгружается, и интерфейс работает даже
  без него.

## Запуск через Docker Compose

```bash
cp .env.example .env          # заполните токены (CANVAS_API_TOKEN может быть пустым)
docker compose up -d --build  # собрать и запустить бота и Caddy (в фоне)
docker compose logs -f bot    # смотреть логи (JSON)
```

Поднимаются два сервиса:

- **bot**: бот, опрос Canvas и Mini App (HTTP на `:8080`, наружу не
  публикуется). База SQLite лежит на томе `bot-data` по пути `/data/bot.db` и
  переживает перезапуски. Состояние контейнера проверяется healthcheck, который
  дёргает `/healthz`.
- **caddy**: завершение HTTPS и автоматический сертификат Let's Encrypt для
  `WEBAPP_DOMAIN`, публикует порты 80 и 443.

Процесс бота работает от непривилегированного пользователя (uid 10001).
Небольшой entrypoint готовит том с данными и сбрасывает привилегии, поэтому
установка, созданная старым образом (от root), продолжает работать после
обновления.

Без `WEBAPP_DOMAIN` приложение просто не показывается в Telegram (в чате
остаётся клавиатура), а Caddy отдаёт локальный сайт-заглушку на `localhost`.
Чтобы запустить только бота без прокси:

```bash
docker compose up -d --build bot
```

Оба контейнера работают с `restart: unless-stopped`, поэтому поднимаются после
перезагрузки.

## Развёртывание на VDS (по шагам)

Подойдёт любой небольшой Linux-сервер (1 vCPU / 1 ГБ RAM / 10 ГБ диска
хватает). С включённым Mini App порты **80 и 443** должны быть доступны из
интернета (порт 80 нужен для проверки Let's Encrypt), поэтому выбирайте хостинг,
где они не закрыты.

**Страну сервера выбирайте осознанно.** Трафик к Canvas должен идти через
казахстанский IP. VDS в Казахстане подходит без прокси; VDS в любом другом
месте требует `CANVAS_PROXY` с казахстанским адресом, иначе университет
заблокирует сервер (см. [Прокси (CANVAS_PROXY)](#прокси-canvas_proxy)).

**a. Подготовьте сервер (один раз).**

```bash
ssh root@YOUR_VDS_IP
apt update && apt upgrade -y
apt install -y ca-certificates curl git ufw
# Docker Engine + compose plugin (официальный скрипт):
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
# Файрвол: SSH внутрь, HTTP+HTTPS внутрь для сертификата Mini App, всё остальное наружу.
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
```

**b. Направьте имя хоста на сервер (DuckDNS).**

1. Откройте <https://www.duckdns.org>, войдите и создайте поддомен, например
   `narxoz-bot`.
2. Укажите в нём IP вашего VDS (DuckDNS → *current ip*).
3. Проверьте откуда угодно: `getent hosts narxoz-bot.duckdns.org` должен вернуть
   IP сервера.

Caddy запросит сертификат для этого хоста автоматически, как только контейнер
запустится с `WEBAPP_DOMAIN=narxoz-bot.duckdns.org`.

**c. Доставьте код на сервер.**

Вариант 1, через git (сначала запушьте репозиторий на GitHub/GitLab):

```bash
git clone <your-repo-url> /opt/narxoz-canvas-bot && cd /opt/narxoz-canvas-bot
```

Вариант 2, копирование с вашей машины (запускайте локально, не на сервере):

```bash
scp -r . root@YOUR_VDS_IP:/opt/narxoz-canvas-bot
```

**d. Настройте секреты.**

```bash
cd /opt/narxoz-canvas-bot
cp .env.example .env
nano .env            # TELEGRAM_BOT_TOKEN=... CANVAS_TOKEN_SECRET=...
chmod 600 .env       # токены читает только root
```

`CANVAS_API_TOKEN` можно оставить пустым: подключите Canvas из чата Telegram
через `/setup` или из Mini App. Задайте случайный `CANVAS_TOKEN_SECRET`, чтобы
введённый в чате токен шифровался в базе
(`tr -dc A-Za-z0-9 </dev/urandom | head -c 32`).

Для Mini App дополнительно задайте (на шаге **b** имя хоста уже создано):

```bash
WEBAPP_DOMAIN=narxoz-bot.duckdns.org
WEBAPP_URL=https://narxoz-bot.duckdns.org
```

**e. Запустите.**

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f --tail 50
```

В логах должны быть `telegram bot is listening for updates`,
`canvas_token":"env"|"chat"|"none"` и, если включено приложение,
`chat menu button points at the mini app`, а также запись Caddy о получении
сертификата. Дальше откройте Telegram, нажмите **/start** и подключите Canvas
через `/setup` или кнопкой **Открыть**.

**f. Переживание перезагрузок.** Уже настроенный в `docker-compose.yml`
`restart: unless-stopped` вместе с включённым сервисом `docker` автоматически
поднимают бота. Проверьте:

```bash
systemctl is-enabled docker
docker compose ls
```

**g. Обновление и эксплуатация.**

```bash
git pull                                    # или скопируйте исходники заново
docker compose up -d --build                # пересобрать и перезапустить
docker compose logs -f --tail 100           # логи
docker compose restart                      # просто перезапустить
docker compose down                         # остановить (том с базой останется)
```

**h. Резервная копия базы** (настройки, отключения курсов, токены чатов):

```bash
docker compose exec -T bot tar czf - -C /data . > "bot-data-$(date +%F).tar.gz"
```

Команда выдаёт архив в текущий каталог и не зависит от имени Docker-тома. Для
восстановления сначала остановите бота, чтобы он не писал в базу во время
распаковки:

```bash
docker compose stop bot
docker compose run --rm --no-deps -T bot sh -c "tar xzf - -C /data" < bot-data-2026-01-01.tar.gz
docker compose up -d bot
```

## Решение проблем

**`Conflict: terminated by other getUpdates request` в логах.**
Два процесса длинного опроса используют один и тот же `TELEGRAM_BOT_TOKEN`.
Telegram допускает ровно один, поэтому сообщения делятся между ними случайным
образом (на `/setup` может ответить один экземпляр, а токен уйдёт в другой).
Держите один экземпляр: сделайте `docker compose down` локально перед запуском
на VDS (и наоборот) и проверьте, не осталось ли лишних процессов через
`docker ps` / `ps aux | grep bot`.

**Нет кнопки «Открыть» в чате.** Она появляется только при заданном
`WEBAPP_URL` и только если бот смог её установить: ищите в логах
`chat menu button points at the mini app`; если вызов не удался (или в логах
`err`), проверьте, что URL начинается с HTTPS и доступен. Повторное открытие
чата или перезапуск бота устанавливают кнопку заново.

**Приложение открывается, но пишет «Откройте приложение из Telegram».**
Запрос не содержал корректного `initData`: открывайте через кнопку бота, а не
вставляя URL в браузер. При заданном `TELEGRAM_CHAT_ID` доступ разрешён
только этому аккаунту, остальные получат «приложение доступно только
владельцу бота».

**Caddy не может получить сертификат.** Порт 80 должен быть доступен из
интернета (проверка HTTP-01), а запись DuckDNS должна указывать на VDS:
`docker compose logs caddy | tail -30`, `getent hosts <your-domain>`.
Сертификаты кэшируются в томе `caddy-data`, поэтому после перезапуска они не
перевыпускаются.

**Caddy перезапускается по кругу сразу после `docker compose up`.** Адрес
сайта в Caddyfile оказался пустым. Задайте `WEBAPP_DOMAIN` настоящим
именем хоста или запустите `docker compose up -d bot` без прокси.

**«Canvas не ответил на проверку» / `context deadline exceeded`.**
Токен всё равно сохраняется (со статусом *ждёт проверки ⏳*) и проверяется в
фоне, поэтому вводить его заново не нужно. Посмотрите исходную ошибку в
настройках приложения или в `docker compose logs | grep canvas`. Типичные
причины:

- хост или контейнер, где работает бот, не достаёт до `CANVAS_BASE_URL`
  (файрвол, сломанный DNS, заблокированный исходящий TLS). Проверьте с
  этого хоста командой
  `curl -sS -o /dev/null -w '%{http_code}\n' -H 'Authorization: Bearer x' \
   https://canvas.narxoz.kz/api/v1/users/self` (для заведомо неверного токена
  ожидается `401`);
- временный сбой Canvas или сети: нажмите кнопку обновления в приложении.

**VDS, чей IP дата-центра заблокирован университетом.** Некоторые хосты (и
целые страны) вообще не могут открыть `canvas.narxoz.kz`: соединение висит до
таймаута. Проверьте с сервера:

```bash
curl -s https://ipinfo.io/json | head -c 200; echo                     # где на самом деле VDS
getent hosts canvas.narxoz.kz                                          # ответ DNS
curl -sS -o /dev/null -w 'http=%{http_code} connect=%{time_connect}s total=%{time_total}s\n' \
  --max-time 20 -4 -H 'Authorization: Bearer x' https://canvas.narxoz.kz/api/v1/users/self
curl -sS -o /dev/null -w 'http=%{http_code} total=%{time_total}s\n' --max-time 20 \
  --resolve canvas.narxoz.kz:443:91.214.174.9 -H 'Authorization: Bearer x' https://canvas.narxoz.kz/api/v1/users/self
```

Если первая команда висит, а вторая с явным IP работает, дело в DNS; если
висят обе, маршрут до IP Canvas фильтруется. Варианты: перенести бота на VDS в
Казахстане, запустить его в сети, которая достаёт до Canvas, либо оставить VDS
и пустить трафик к Canvas через прокси с казахстанским IP:

```dotenv
# .env на VDS
CANVAS_PROXY=socks5://user:pass@kz-proxy-host:1080
```
`CANVAS_PROXY` влияет только на Canvas: Telegram по-прежнему ходит напрямую.
Прокси по умолчанию выключен, поэтому его нужно включить явно.

**«Canvas отклонил токен (401/403)».** Неверён сам токен (выдан не на
`CANVAS_BASE_URL`, истёк или скопирован не полностью). Сгенерируйте новый и
снова отправьте `/setup`.

**Бот не отвечает.** Смотрите `docker compose logs -f`: процесс пишет в логи
строку о запуске и каждую ошибку опроса в JSON. Состояние Canvas и подключения
можно посмотреть через `/status` или на вкладке настроек в приложении.

**Базу данных не удаётся открыть.** Родительский каталог `DB_PATH` создаётся
автоматически, поэтому обычно это проблема с правами. Проверьте, что том
`bot-data` доступен на запись пользователю контейнера.

## Как работает время

Canvas возвращает метки времени в ISO-8601 UTC. Они хранятся в UTC и
переводятся в `TZ` (`Asia/Almaty`, UTC+5) для показа и для расчёта
напоминаний. У Asia/Almaty нет перехода на летнее время, а если в системе нет
`tzdata`, код использует фиксированную зону `UTC+5`, поэтому бинарник ведёт
себя одинаково на тонком Alpine-образе.

## Тесты

```bash
make test    # go test ./... -count=1
```

Юнит-тесты покрывают чистую логику сверки и напоминаний (новое задание, новая
оценка, напоминание срабатывает только по несданным, просрочка срабатывает

У Mini App свои тесты: подпись и проверка `initData` (валидный, подделанный,
чужой токен, устаревший, dev-режим) и весь JSON API на фейковом Canvas и

неверный токен отклоняется, сообщение с токеном удаляется, токен сохраняется в

появляются в чате.

# или: LIVE_CANVAS=1 LIVE_CANVAS_URL=https://your-canvas.example go test ...
